Phase 1 ~ 7 개요

Phase 1
- 설명: 서버를 처음 실행했을 때 홈페이지 UI만 보여짐. 디자인 확인용이고 아무런 기능이 없어야 함.
- 완료기준 체크리스트:
  - [ ] 서버가 정상 기동되어 홈페이지가 로드된다.
  - [ ] 홈페이지는 기본 레이아웃(헤더/메인/푸터)을 보여준다.
  - [ ] UI는 정적이며, 버튼이나 링크는 기능을 수행하지 않는다.
  - [ ] 반응형(기본) 레이아웃이 동작한다.

Phase 2
- 설명: 상단의 네비게이션 바에는 부산 게시판, 지도, 대시보드, 축제 캘린더, 북마크가 있고 홈페이지에서도 간단히 확인할 수 있음.
- 완료기준 체크리스트:
  - [ ] 상단 네비게이션 바가 디자인에 맞춰 노출된다.
  - [ ] 네비게이션 항목: 부산 게시판, 지도, 대시보드, 축제 캘린더, 북마크가 표시된다.
  - [ ] 각 항목은 비활성 링크(또는 라우트 플레이스홀더)로 존재한다.
  - [ ] 홈페이지 메인에서 각 메뉴의 간단한 요약(문구/아이콘) 확인 가능.

Phase 3
- 설명: SPA 방식으로 부산 게시판을 클릭하면 게시판은 CRUD 기능을 가져서 사용자가 게시글을 작성할 수 있음.
- 완료기준 체크리스트:
  - [ ] 부산 게시판 페이지가 SPA 라우팅으로 동작한다.
  - [ ] 게시글 목록 조회가 동작한다(목록은 초기 더미/샘플 데이터로 표시 가능).
  - [ ] 게시글 작성(Create) 폼이 있고, 작성 후 목록에 반영된다.
  - [ ] 게시글 상세(Read), 수정(Update), 삭제(Delete) 기능이 동작한다(간단한 로컬 스토리지 또는 임시 API 사용 가능).

Phase 4
- 설명: SPA 방식으로 지도를 클릭하면 부산 지도가 보이고, 음식점, 축제공연행사, 문화시설, 레포츠, 숙박, 쇼핑, 여행코스를 각각 클릭해서 볼 수 있음.
- 완료기준 체크리스트:
  - [ ] 지도 페이지가 SPA 라우팅으로 동작한다.
  - [ ] 기본 부산 지도(임베드 또는 샘플 이미지/지도 라이브러리)가 표시된다.
  - [ ] 카테고리 버튼(음식점, 축제공연행사, 문화시설, 레포츠, 숙박, 쇼핑, 여행코스)이 존재한다.
  - [ ] 각 카테고리 클릭 시 해당 카테고리의 POI 목록 또는 마커가 지도에 표시된다(더미 데이터 허용).

Phase 5
- 설명: SPA 방식으로 대시보드를 클릭하면 부산 관광 데이터 * 커뮤니티 현황 통계를 표와 차트로 확인할 수 있음.
- 완료기준 체크리스트:
  - [ ] 대시보드 페이지가 SPA 라우팅으로 동작한다.
  - [ ] 표 형태의 통계(간단한 행/열)가 표시된다.
  - [ ] 차트(막대/선/원형 등)가 1개 이상 표시된다(예: 방문자 수, 게시글 수 등 더미 데이터로 표현).
  - [ ] 표와 차트는 동일한 더미 데이터 원본을 참조한다.

Phase 6
- 설명: 축제 캘린더를 클릭하면 축제행사 캘린더를 볼 수 있고, 부산 권역 축제공연 행사 정보 갱신일 기준 배치가 되어있음.
- 완료기준 체크리스트:
  - [ ] 축제 캘린더 페이지가 SPA 라우팅으로 동작한다.
  - [ ] 월별 캘린더 뷰에서 축제/행사 항목을 확인할 수 있다.
  - [ ] 각 행사에는 갱신일(또는 업데이트 날짜) 필드가 표시된다.
  - [ ] 갱신일 기준으로 정렬 또는 배치가 가능한 인터페이스가 존재한다(간단한 정렬 버튼으로 충분).

Phase 7
- 설명: SPA 방식으로 북마크를 클릭하면 사용자가 북마크한 게시글을 볼 수 있음.
- 완료기준 체크리스트:
  - [ ] 북마크 페이지가 SPA 라우팅으로 동작한다.
  - [ ] 사용자가 게시글 목록에서 북마크를 추가/제거할 수 있다(로컬 저장소 허용).
  - [ ] 북마크 페이지는 사용자가 북마크한 게시글만 필터링하여 표시한다.
  - [ ] 북마크 데이터는 세션 또는 로컬스토리지에 보존된다.
